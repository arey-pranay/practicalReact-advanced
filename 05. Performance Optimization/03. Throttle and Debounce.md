# Throttling & Debouncing

These are easiest if you **stop memorizing implementations** and first understand the timing problem.

Both answer:

> **“I have a function that is being called too many times. When should I actually allow the function to run?”**

---

# 1. Why do we need them?

Some browser events fire extremely frequently:

```text
scroll       → many times per second
mousemove    → many times per second
resize       → many times per second
input        → every keystroke
```

Suppose:

```js
window.addEventListener("scroll", () => {
  expensiveCalculation();
});
```

If the user scrolls for 2 seconds:

```text
scroll scroll scroll scroll scroll scroll scroll...
 ↓     ↓     ↓     ↓     ↓     ↓
calc  calc  calc  calc  calc  calc
```

You might not need to run `expensiveCalculation()` every time.

So we introduce a timing policy.

---

# 2. The Core Difference

## Throttle

> **Run at most once every X milliseconds while events keep happening.**

Think:

```text
Events:
🔥🔥🔥🔥🔥🔥🔥🔥🔥🔥🔥🔥

Throttle 1000ms:

🔥           🔥           🔥
│            │            │
0ms         1000ms       2000ms
```

It keeps running **during** the activity, but limits the frequency.

### Real-world analogy

A security guard says:

> "I will let one person in every 1 second."

People keep arriving → one gets through every second.

---

# 3. Debounce

> **Wait until events stop happening for X milliseconds, then run once.**

```text
Events:
🔥🔥🔥🔥🔥🔥🔥🔥

Debounce 1000ms:

🔥🔥🔥🔥🔥🔥🔥🔥
                │
                ↓
              wait
                ↓
             1000ms
                ↓
                🔥
```

Every new event **resets the timer**.

### Real-world analogy

Someone keeps saying:

> "Wait... I have one more thing to say."

You only respond after they've been silent for 1 second.

---

# 4. The Easiest Way to Remember

### Throttle

```text
"Keep doing it, but not too often."
```

### Debounce

```text
"Don't do it until they stop."
```

That's the entire conceptual difference.

---

# 5. When Would I Use Which?

| Situation                                          | Usually              |
| -------------------------------------------------- | -------------------- |
| Scroll position tracking                           | Throttle             |
| Mouse movement                                     | Throttle             |
| Window resize                                      | Throttle or debounce |
| Search API while typing                            | Debounce             |
| Autosave after typing stops                        | Debounce             |
| Form validation after typing                       | Debounce             |
| Button repeatedly clicked                          | Throttle             |
| Analytics for continuous scrolling                 | Throttle             |
| Expensive calculation after user finishes resizing | Debounce             |

# 6. First Learn Debounce

Debounce is easier to implement.

Start with the requirement:

> "Every time the function is called, wait 500ms. If another call happens before 500ms, cancel the previous wait and start again."

We need:

```js
let timer;
```

Why?

Because we need to remember the previous timer.

---

# 7. Simplest Debounce Implementation

```js
function debounce(callback, delay) {
  let timer;

  return function (...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      callback(...args);
    }, delay);
  };
}
```

That's the implementation you should understand deeply.

---

# 8. Let's Build It Step by Step

Start with:

```js
function debounce(callback, delay) {
```

We need to return another function because we don't want to execute `callback` immediately.

```js
function debounce(callback, delay) {
  let timer;

  return function (...args) {
    // ...
  };
}
```

Now every call enters here:

```js
return function (...args) {
```

Suppose:

```js
debouncedSearch("r");
debouncedSearch("re");
debouncedSearch("rea");
debouncedSearch("reac");
debouncedSearch("react");
```

Each call needs to cancel the previous timer:

```js
clearTimeout(timer);
```

Then create a new timer:

```js
timer = setTimeout(() => {
  callback(...args);
}, delay);
```

So the complete flow becomes:

```text
Call 1
 ↓
start timer

Call 2 before timer finishes
 ↓
cancel timer 1
 ↓
start timer 2

Call 3
 ↓
cancel timer 2
 ↓
start timer 3

Call 4
 ↓
cancel timer 3
 ↓
start timer 4

No more calls
 ↓
timer finally finishes
 ↓
callback()
```

# 11. Why `...args`?

Suppose:

```js
const save = debounce((name, age) => {
  console.log(name, age);
}, 500);
```

We want:

```js
save("Pranay", 22);
```

to eventually call:

```js
callback("Pranay", 22);
```

Therefore:

```js
return function (...args) {
  clearTimeout(timer);

  timer = setTimeout(() => {
    callback(...args);
  }, delay);
};
```

`...args` forwards whatever arguments were supplied.

---

# 12. Why Do We Return a Function?

This is a very important JavaScript concept.

When you do:

```js
const search = debounce(callback, 500);
```

`debounce()` itself doesn't become the search function.

It creates and returns one:

```text
debounce(callback, 500)
        ↓
returns function
        ↓
search
        ↓
search(...)
```

That returned function owns the `timer` variable through a **closure**.

```text
debounce()
│
├── timer
│
└── returned function
       │
       └── can access timer
```

This closure is the heart of debounce.

# 13. Now Throttle

Throttle has a different requirement:

> "Once the function runs, don't allow it to run again for X milliseconds."

The simplest implementation uses a timestamp.

```js
function throttle(callback, delay) {
  let lastRun = 0;

  return function (...args) {
    const now = Date.now();

    if (now - lastRun >= delay) {
      lastRun = now;
      callback(...args);
    }
  };
}
```

---

# 14. Understand Throttle Before Memorizing It

Suppose:

```js
const handleScroll = throttle(
  () => {
    console.log("scroll");
  },
  1000,
);
```

Events:

```text
0ms
100ms
200ms
300ms
400ms
500ms
600ms
700ms
800ms
900ms
1000ms
```

At `0ms`:

```text
now - lastRun >= 1000
```

Initially:

```text
lastRun = 0
```

Depending on implementation details, the first call can be handled specially. A cleaner implementation is often:

```js
let lastRun = -Infinity;
```

Then:

```text
0ms → RUN
100ms → ignore
200ms → ignore
...
900ms → ignore
1000ms → RUN
```

So:

```text
🔥           🔥           🔥
│            │            │
0ms         1000ms       2000ms
```

# 15. Better Basic Throttle

```js
function throttle(callback, delay) {
  let lastRun = -Infinity;

  return function (...args) {
    const now = Date.now();

    if (now - lastRun >= delay) {
      lastRun = now;
      callback(...args);
    }
  };
}
```

That's the **leading-only throttle**.

It runs immediately and then blocks subsequent calls until the interval has passed.

# 19. React Example: Debounce

One important React issue:

**Don't recreate the debounced function on every render.**

Bad:

```jsx
function Search() {
  const search = debounce((query) => {
    fetchResults(query);
  }, 500);

  return (
    <input
      onChange={(e) => search(e.target.value)}
    />
  );
}
```

Every render creates a new debounce closure:

```text
Render 1 → debounce A → timer A
Render 2 → debounce B → timer B
Render 3 → debounce C → timer C
```

Now your timer state is not stable.

---

# 20. Stable Debounce in React

You can use `useMemo()`:

```jsx
function Search() {
  const search = useMemo(
    () =>
      debounce((query) => {
        fetchResults(query);
      }, 500),
    [],
  );

  return (
    <input
      onChange={(e) => {
        search(e.target.value);
      }}
    />
  );
}
```

Now:

```text
Component renders
      ↓
useMemo
      ↓
same debounced function
      ↓
same timer closure
```

### Or `useCallback()`?

Technically:

```jsx
const search = useCallback(
  debounce((query) => {
    fetchResults(query);
  }, 500),
  [],
);
```

can work, but `useMemo()` communicates the intent more clearly here because you are memoizing the **result of calling `debounce()`**, which is a function.

---

# 21. But There Is a Stale Closure Problem

Consider:

```jsx
const search = useMemo(
  () =>
    debounce(() => {
      console.log(query);
    }, 500),
  [],
);
```

`query` can become stale because the debounced function was created only once.

A better pattern is to pass the changing value as an argument:

```jsx
const search = useMemo(
  () =>
    debounce((query) => {
      fetchResults(query);
    }, 500),
  [],
);
```

Then:

```jsx
onChange={(e) => {
  search(e.target.value);
}}
```

Now the latest value travels through the function argument rather than being captured from an old render.

---

# 22. Cleanup in React

Timers should be cleaned up when the component unmounts.

A production-quality debounce can expose a `cancel()` method:

```js
function debounce(callback, delay) {
  let timer;

  function debounced(...args) {
    clearTimeout(timer);

    timer = setTimeout(() => {
      callback(...args);
    }, delay);
  }

  debounced.cancel = () => {
    clearTimeout(timer);
  };

  return debounced;
}
```

Then:

```jsx
function Search() {
  const search = useMemo(
    () =>
      debounce((query) => {
        fetchResults(query);
      }, 500),
    [],
  );

  useEffect(() => {
    return () => {
      search.cancel();
    };
  }, [search]);

  // ...
}
```

This prevents a pending timer from firing after the component has been removed.

# 23. `useDeferredValue` Is NOT Debouncing

This is especially important given your previous React topics.

You learned:

```jsx
const deferredQuery =
  useDeferredValue(query);
```

That is **not** equivalent to:

```js
debounce(query, 500);
```

### Debounce

Controls **when your function runs**.

```text
typing
 ↓
wait for silence
 ↓
run function
```

### `useDeferredValue`

Controls **React rendering priority**.

```text
new value
 ↓
urgent update
 ↓
React can defer expensive UI
```

There is no fixed `500ms` timer.

---

# 24. Throttle vs Debounce vs `useDeferredValue`

|                             | Throttle           | Debounce             | `useDeferredValue`   |
| --------------------------- | ------------------ | -------------------- | -------------------- |
| Controls                    | Function frequency | Function timing      | Render priority      |
| Fixed delay                 | Yes                | Yes                  | No                   |
| Waits for silence           | No                 | Yes                  | No                   |
| API request control         | Yes, but periodic  | Excellent for search | No                   |
| Scroll handling             | Excellent          | Usually not ideal    | Not the same problem |
| Expensive React UI          | Not primarily      | Not primarily        | Excellent use case   |
| Prevents function execution | Yes                | Yes                  | No                   |

# 26. How to Identify the Right Technique

When you see a high-frequency event, ask:

### Question 1

> **Do I want the function to keep running while the activity continues?**

Yes:

```text
THROTTLE
```

Example:

```text
scroll → update position every 100ms
```

### Question 2

> **Do I only care about the final action after the user stops?**

Yes:

```text
DEBOUNCE
```

Example:

```text
typing → search after 500ms silence
```

### Question 3

> **Is the actual problem React rendering priority rather than too many function calls?**

Consider:

```text
useTransition
useDeferredValue
```

# 27. How to Come Up With the Implementation Yourself

Don't memorize the code.

Start with the English requirement.

## Debounce

> "Every call should restart a timer."

Translate:

```text
Need timer
    ↓
clear previous timer
    ↓
create new timer
```

Therefore:

```js
let timer;

return (...args) => {
  clearTimeout(timer);

  timer = setTimeout(() => {
    callback(...args);
  }, delay);
};
```

Done.

---

## Throttle

> "Once I run, don't run again until X milliseconds have passed."

Translate:

```text
Need to remember last execution
    ↓
Get current time
    ↓
Compare current time - last execution
    ↓
If enough time passed → run
```

Therefore:

```js
let lastRun = -Infinity;

return (...args) => {
  const now = Date.now();

  if (now - lastRun >= delay) {
    lastRun = now;
    callback(...args);
  }
};
```

Done.

# 28. One More Important Throttle Variant

You will encounter throttles with **leading + trailing** behavior.

Example:

```text
Events:
🔥🔥🔥🔥🔥🔥🔥🔥🔥

Throttle 1000ms:

🔥           🔥
│            │
RUN          RUN
             ↑
          last event
```

A trailing throttle remembers the **last call** that happened during the blocked period and executes it after the interval.

This is why real-world throttle implementations can look considerably more complicated than the basic timestamp version.

For interviews, first understand the simple version:

```js
if (now - lastRun >= delay) {
  lastRun = now;
  callback();
}
```

Then learn leading/trailing options.

### Interview revision

> **Throttle limits a function to at most once per interval while events continue; debounce resets a timer on every call and executes only after the calls stop. Throttle is commonly used for continuous events like scroll, while debounce is common for search/input where only the final value matters. Both rely on closures to preserve timing state across calls.**
